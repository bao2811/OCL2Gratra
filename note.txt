M0 object links

MATCH (a)-[r]->(b)

# Plan Mapping OCL -> Cypher

## Muc tieu

Xay dung bo mapping OCL sang Cypher theo huong chinh xac, co kiem chung, va giam so lan query Neo4j. Muc tieu khong chi la "dich text OCL thanh Cypher", ma la tao mot pipeline co semantic binding ro rang:

`OCL text -> AST -> Semantic Binding -> Query IR -> Optimized Cypher Plan -> Execute -> Validation Report`

Trong TGG runtime, bo mapping nay se duoc dung cho:

- Kiem invariant cua source, target, correspondence truc tiep tren Neo4j.
- Kiem guard/rule applicability truoc khi forward/backward/sync.
- Sinh query match pattern cho TGG thay vi hardcode tung demo.
- Dong bo lai khi model/XMI/instance thay doi ma khong can load toan bo ve USE.

## Hien trang trong module neo4j

Module `neo4j` hien co hai nhanh OCL chinh:

- `org.uet.dse.neo4j.oclite`: parser/evaluator rieng, dung `OCLLexer`, `OCLParser`, `ASTVisitor`, `ExpressionBinder`, `ExecutionContext`, `Neo4jRepository`.
- `org.uet.dse.neo4j.ocl`: nhanh cu hon, co `NExpressionRewriter`, `NEvaluator`, `NExpression`, `NStandardOperations...`, nhung phan UI hien tai dang nghieng ve `oclite`.

Luong dang chay trong `OclEvaluatorDialog`:

1. Doc OCL text tu UI.
2. Parse bang ANTLR `OCLLexer/OCLParser`.
3. Tao AST bang `ASTVisitor`.
4. Bind AST sang cay evaluator bang `ExpressionBinder`.
5. Neu la `context Class inv name: expr`, lap qua tung object cua class do.
6. Voi moi object, tao `ExecutionContext`, gan `self`, roi evaluate Java.
7. Khi can du lieu, `ExecutionContext` goi `Neo4jRepository`.

Cac query Neo4j hien tai trong `Neo4jRepository`:

- `findAllInstancesOfClass(className)`: tim tat ca M0 object instance cua class.
- `findNodeById(use_id)`: tim object theo `use_id`.
- `getAttributeValue(node, attrName)`: query attribute qua `ObjectHasAttribute -> AttributeValue`.
- `findRelatedNodes(node, roleName)`: query link instance voi relationship type bat dau bang `Link`, loc theo `sourceRole`, `targetRole`, hoac `name`.
- `checkClassExistsInDb(className)`: kiem class trong metamodel.
- `isVariableExist(varName)`: kiem object instance co ton tai.
- `isRelationship(source, name)`: kiem navigation dua tren metamodel association.

Van de cua nhanh nay:

- Evaluator Java gay nhieu query nho. Vi du invariant tren 1000 object co the thanh 1000+ query attribute/navigation.
- Chua co query plan toan cuc, khong toi uu duoc join/path.
- `isRelationship` phu thuoc cach lay type cua source; voi `self` hoac iterator local, type inference con yeu.
- Navigation dang loc theo relationship property `sourceRole`, `targetRole`, `name`; neu schema link instance khong dong nhat thi de sai hoac miss.
- Attribute value dang luu dang string/OCL literal nen phai normalize nhieu lan.
- Bao loi parse/semantic chua than thien, mot so message bi loi encoding.

## Hien trang trong module neo4j-tgg

Module `neo4j-tgg` co nhanh OCL -> Cypher truc tiep:

- Interface: `OclToCypherCompiler`
- Implementation: `DefaultOclToCypherCompiler`
- Ket qua: `CypherCompilationResult`
- Validation: `DefaultOclValidationService`
- UI: `WorkspaceGraphView` goi `getOclValidationService().validate(...)`

Luong dang chay trong TGG workspace:

1. Lay `MModel` cua side dang validate tu `TggWorkspaceDefinition`.
2. Compile OCL bang `DefaultOclToCypherCompiler`.
3. Neu compiler support va AST la context invariant, chay Cypher sinh ra tren Neo4j.
4. Query tra ve danh sach `self.use_id` bi vi pham.
5. Neu compiler khong support, fallback ve evaluator Java cua `neo4j/oclite`.

Dang support trong `DefaultOclToCypherCompiler`:

- `context Class inv name: expr`
- Bien `self`
- Class reference + `allInstances()`
- Literal string/integer/real/boolean/null
- Binary operator: `=`, `<>`, `and`, `or`, `implies`, `>`, `<`, `>=`, `<=`, `+`, `-`, `*`, `/`
- `not`
- Attribute access qua `ObjectHasAttribute -> AttributeValue`
- Navigation qua link relationship co type bat dau bang `Link`
- Method: `split`, `isDefined`, `isUndefined`
- Collection op: `size`, `isEmpty`, `notEmpty`, `at`
- Iterator: `select`, `exists`, `forall`, `collect`

Dang tao query dang:

```cypher
MATCH (self)-[:ObjectInstanceOf]->(cls {name: $className})
WHERE NOT coalesce(<compiled expression>, false)
RETURN self.use_id AS useId
```

Han che hien tai:

- Dang compile truc tiep AST -> Cypher string, chua co IR nen kho toi uu va kho kiem chung.
- Chi support invariant context; chua support query expression, pre/post, let, if, enum, tuple, closure, includes/excludes day du.
- Type binding con don gian: node, node collection, scalar, scalar collection, class reference.
- Navigation binding dua tren `MClassImpl.navigableEnd`, nhung Cypher runtime van match link chung chung bang `type(r) STARTS WITH 'Link'`.
- Collection semantics chua day du theo OCL, dac biet null/undefined, Set/Bag/Sequence, flatten, includesAll.
- `at()` dang default scalar String, chua lay element type tu source collection.
- Chua co cost model, chua co cache metamodel, chua co explain/profile.
- Fallback Java van co nguy co query tung object/tung property, nen cham voi data lon.

## Kien truc de xuat

### 1. Parser Layer

Dung mot parser chinh thuc duy nhat cho runtime:

- Input: OCL text.
- Output: AST co vi tri source, token range, loi parse ro rang.
- Viec can lam: thong nhat `oclite` AST va compiler TGG, tranh co nhieu cay AST rieng le.

Ket qua mong muon:

- `OclParseResult`
- `OclAst`
- `ParseDiagnostic`

### 2. Semantic Binding Layer

Binding phai bien AST thanh cay co type va metadata:

- Resolve class, attribute, association, role, enum, operation.
- Resolve `self`, iterator variable, let variable.
- Gan type OCL chinh xac: `Boolean`, `Integer`, `Real`, `String`, `Class`, `Set(T)`, `Sequence(T)`, `Bag(T)`, `Void`, `Invalid`.
- Gan source side: source/target/corr cho TGG.
- Kiem loi som: unknown class, unknown attribute, wrong iterator source, wrong operation arity.

Output:

- `BoundOclExpression`
- `BoundVariable`
- `BoundNavigation`
- `BoundAttribute`
- `BoundOperation`
- `SemanticDiagnostic`

Day la lop quan trong nhat de tranh query sai.

### 3. Query IR Layer

Khong sinh Cypher truc tiep tu AST. Can tao IR trung gian:

- `NodeScan(className, alias)`
- `AttributeRead(ownerAlias, attrName, valueAlias)`
- `NavigationJoin(sourceAlias, associationName, roleName, targetAlias)`
- `Filter(predicate)`
- `Projection(expr)`
- `Aggregation(kind)`
- `Quantifier(any/all/none)`
- `CollectionMap/select/collect`
- `ExistsSubquery`
- `ViolationQuery(contextClass, invariantName, predicate)`

IR giup:

- Toi uu join.
- Gom nhieu property/navigation vao mot query.
- Sinh Cypher on dinh.
- Test compiler ma khong can Neo4j.

### 4. Cypher Planner

Bien IR thanh Cypher plan:

- Chon query shape: single MATCH, EXISTS subquery, pattern comprehension, CALL subquery.
- Day filter cang som cang tot.
- Reuse alias cho cung mot navigation/property.
- Parameterize tat ca literal.
- Tao query return violation/detail.

Output:

- `CypherPlan`
- `cypher`
- `parameters`
- `projectedColumns`
- `estimatedCost`
- `warnings`

### 5. Execution Layer

Chay Cypher tren Neo4j theo read transaction:

- Support database name.
- Timeout.
- Explain/profile optional.
- Log query + params.
- Return structured result, khong chi text.

Output:

- `OclExecutionResult`
- `violations`
- `rows`
- `timing`
- `fallbackUsed`
- `diagnostics`

### 6. Equivalence Check Layer

Can co che do kiem OCL voi Cypher:

- Chay evaluator Java va Cypher tren cung input nho.
- So sanh result.
- Neu khac, bao query, AST, IR, row mismatch.
- Dung cho regression test va de tang do tin cay compiler.

Day la phan bat buoc vi OCL semantics rat de sai, dac biet collection/null/navigation.

## Ket luan hien tai

Hien tai project da co nen tang ban dau: parse OCL, AST, fallback evaluator tren Neo4j, va mot compiler OCL -> Cypher subset trong `neo4j-tgg`. Tuy nhien muc hien tai van la prototype: compiler con sinh Cypher truc tiep tu AST, navigation con loose, fallback con query nhieu, va chua co IR/toi uu/semantic check day du.

Buoc dung nhat tiep theo la khong viet them rule hardcode, ma tap trung tao `Semantic Binder + Query IR + Cypher Planner`. Khi co lop nay, no se phuc vu dong thoi invariant validation, TGG forward, backward, va sync.

Bước tiếp theo hợp lý là đẩy tối ưu này lên một mức nữa:

rewrite select(...)->isEmpty/notEmpty/size() thành một IR node riêng thay vì để renderer tự nhận pattern
từ đó chuẩn bị cho các operation khác như includes, excludes, includesAll, và về sau planner có thể chọn EXISTS, COUNT, hoặc list comprehension một cách có chủ đích hơn.

Findings

OclMetamodelIndex đang bind kiểu navigation bằng associationEnd.getType() mà không truyền source context, nên có nguy cơ bind sai với qualified association, association redefinition, hoặc một số case n-ary. Điều này sẽ làm IR đúng về cú pháp nhưng sai semantic trước khi tới renderer. Xem OclMetamodelIndex.java.

Renderer vẫn encode navigation bằng pattern vô hướng -[r]- cộng điều kiện r.targetRole OR r.sourceRole, tức vẫn chưa thật sự dùng fully-bound source end/destination end. Với self-association, nhiều end cùng class, hoặc schema link có role metadata không đối xứng, query có thể match thừa hoặc sai hướng. Đây là rủi ro lớn nhất còn lại trong phần “đã tối ưu”. Xem OclCypherRenderer.java, OclCypherRenderer.java.

Optimizer hiện nằm trực tiếp trong renderer dưới dạng pattern matching vào IR tổng quát (size, select, exists, forall), chưa thành một planner phase riêng. Kết quả là logic tối ưu bị phân tán, khó chứng minh tính đúng đắn, và rất dễ gãy khi thêm operation mới như includes, excludes, includesAll, flatten. Đây chưa phải bug ngay bây giờ, nhưng là điểm sẽ làm chậm tiến độ hoàn thiện. Xem OclCypherRenderer.java, OclCypherRenderer.java, OclCypherRenderer.java.

Binder mới vẫn còn type system khá “mỏng”: không có phân biệt Set/Bag/Sequence/OrderedSet, chưa có null/invalid semantics thật, và collect chỉ suy kiểu mức bề mặt. Những tối ưu hiện tại vì vậy đúng cho subset demo nhưng chưa đủ tin cậy cho OCL tổng quát. Xem OclSemanticBinder.java, OclSemanticBinder.java.

Error handling của compiler vẫn dồn hầu hết lỗi vào UnsupportedOperationException, nên chưa có diagnostic đủ tốt cho semantic failure. Khi phạm vi hỗ trợ tăng lên, cách này sẽ làm khó debug mismatch giữa binder, IR và renderer. Xem DefaultOclToCypherCompiler.java.

Phần đã cải thiện là đúng hướng và có tiến bộ thật:

Đã tách binder -> IR -> renderer, không còn compiler “1 cục”.
Đã có metamodel index riêng.
Đã tối ưu được exists, forall, isEmpty/notEmpty, size() trên navigation sang EXISTS hoặc COUNT.
Test đơn vị cho subset hiện tại khá ổn, và trạng thái gần nhất là mvn -pl neo4j-tgg test pass 12 test.
Điểm quan trọng là phần này vẫn nên xem là “subset compiler có planner prototype”, chưa phải semantic engine hoàn chỉnh.

Cần nâng cấp tiếp

Nâng NavigationInfo thành binding đầy đủ:
gồm source end, target end, association name, direction, multiplicity, orderedness.
Khi đó renderer không còn phải match vô hướng.

Tách optimizer khỏi renderer:
thêm một phase kiểu OclIrRewriter hoặc CypherPlanningPass.
Các rewrite select(...)->notEmpty, size()>0, forall, exists nên chạy ở đây, không nằm trong render function.

Mở rộng type system thực sự:
phân biệt Set/Bag/Sequence/OrderedSet;
theo dõi element type chuẩn;
chuẩn hóa null/undefined/invalid.

Bổ sung dual-check test:
cùng một OCL chạy cả fallback Java và Cypher trên dataset nhỏ, rồi so sánh kết quả.
Đây là chỗ quan trọng nhất để bắt sai semantic sớm.

Tăng coverage cho các case khó:
self-association;
nhiều association end cùng class;
empty collection;
nested iterator;
size() = 1, < 1, <> 0;
string/boolean/integer normalization ở attribute value;
inherited navigation/attribute.

Thêm structured diagnostics:
thay UnsupportedOperationException bằng parse/semantic/planning diagnostic riêng, có source location nếu được.

fallback mode: OCL AST -> ExpressionBinder -> ExpressionNode.evaluate(...) trên từng object lấy từ Neo4jRepository

Nếu bạn muốn, tôi có thể chỉ tiếp chính xác findAllInstancesOfClass(...) nằm ở đâu và fallback đang đọc attribute/link từ Neo4j bằng query nào.

Có. native mode tối ưu hơn fallback mode chủ yếu ở 5 điểm:

Chạy set-based thay vì object-by-object
native: một câu Cypher kiểm tra trên cả tập object cùng lúc.
fallback: lấy từng self, rồi evaluate từng object một.
Tận dụng query planner của Neo4j
native dùng optimizer, execution plan, index, pattern matching của Neo4j.
fallback chạy logic ở Java nên không hưởng hết các tối ưu này.
Giảm số lần round-trip / truy cập dữ liệu
native: thường 1 query cho 1 invariant.
fallback: dễ thành findAllInstancesOfClass(...) rồi lại đọc thêm attribute/link khi evaluate, tức nhiều lần truy cập hơn.
Lọc vi phạm ngay trong DB
native: Neo4j chỉ trả về các object vi phạm.
fallback: app phải tự duyệt, tự tính, tự quyết định pass/fail.
Scale tốt hơn khi dữ liệu lớn
Với invariant có navigation, exists, forAll, join giữa nhiều node:
native thường nhanh hơn nhiều
fallback tăng chi phí gần theo số object và số navigation cần kiểm tra
Hiểu ngắn gọn:

native mạnh ở hiệu năng và khả năng scale
fallback mạnh ở độ bao phủ biểu thức khi compiler chưa support
Đổi lại, native chỉ tốt khi compiler dịch đúng và đủ. Nếu OCL quá phức tạp hoặc translator chưa support, fallback là đường lui để vẫn có kết quả.

Ví dụ với Family ::HasFather:

native: Neo4j tự kiểm tra toàn bộ Family nào có/không có link father
fallback: Java lấy từng Family, rồi hỏi từng object xem có father không

Hiện tại pipeline đang là:

Parse cả file OCL một lần.
Tách thành từng rule / từng invariant.
Với mỗi rule:
thử compile sang Cypher
nếu compile được thì chạy query Neo4j cho rule đó
nếu không compile được thì chạy fallback cho rule đó
Cuối cùng gom tất cả rule result lại thành document-level response.

Đúng.

Ở fallback mode, về bản chất là kiểm tra thủ công bằng Java, nhưng không phải viết tay từng invariant riêng lẻ. Thay vào đó:

OCL được parse thành AST
AST được bind thành expression node
Java evaluator chung chạy expression đó trên từng object
Nên chính xác hơn là:

không phải thủ công theo kiểu hardcode từng rule
mà là interpreter Java tổng quát tự kiểm tra rule OCL trên dữ liệu lấy từ Neo4j
Hiểu ngắn gọn:

native = để Neo4j kiểm tra
fallback = để Java interpreter kiểm tra
Ví dụ:

self.name <> ''
self.father->size() > 0
thì fallback sẽ tự evaluate chúng bằng code Java trên từng self.

Nếu muốn nói một câu thật ngắn trong update.md, bạn có thể ghi:

Fallback mode = Java-based manual evaluation over Neo4j-loaded context objects, instead of Neo4j-native Cypher execution.
Hoặc tiếng Việt:

Fallback mode = đánh giá OCL bằng interpreter Java trên từng
